# 碧蓝档案回合制群战

4v4 回合制 PvP，跑在 QQ 群里。**角色数值、技能、战斗公式全部照搬原作**，不自己配平——所以任何"手动调某个角色数值"的需求，先确认是不是该改折算口径而不是改数据。

工作目录：`plugins/sakura-plugin/`

## 加角色（最常见的任务）

三步，都是跑脚本，不要手写 `roster.js`：

```bash
# 1. 在 scripts/emit-roster.mjs 顶部的 IDS 数组里加 [SchaleDB的Id, 内部代号]
#    代号用大写罗马字（HOSHINO/SHIROKO…），会成为素材目录名
# 2. 重新生成角色表（直接写入 lib/ba/roster.js）
node scripts/emit-roster.mjs
# 3. 下载立绘/Q版/头像（已存在的跳过，加 --force 重下）
node scripts/fetch-art.mjs
```

查角色 Id：`scripts/students.json` 里搜中文名。注意**同名多版本**——`白子` 有骑行/泳装/恐怖四个，`野宫`/`芹香` 的初始版是 `13004`/`13008`（2★），不要拿到泳装版。

生成后看告警行。`丢弃 X（原因）` 是正常的（击退等无对应物）；`未映射 X` 说明遇到了没处理过的效果类型，要去 `emit-roster.mjs` 的 `buildSkill` 里补 case。

**还有一批角色不能上架**，`Special` / `Summon` / `Accumulation` 要逐个手写逻辑。目前只做了两种：

- `Summon` 里**攻击力为 0 的挡刀型**（见「召唤物」），会打人的炮台还没有行动逻辑
- `Special` 里 **`Key: "FormChange"`** 的换弹强化（见「换弹强化」），其余 Key 仍然不认

判断在 `unbuildable()`，别用效果类型名一刀切 —— 那会把已经做掉的一起挡在外面。

加完记得 `baBattleImageGenerator.clearCache()` 或重启，否则图鉴还是旧的。

**告警之外还要肉眼扫一遍生成的技能，并对着原作描述核一遍**。这几类错法压测全查不出来
（不变量都满足），全是加 12 个角色时现场抓到的：

- **伤害打到自己身上**。原数据的 `Damage` 效果不写 `Target`，隐含打敌方；只看 Target 列表
  会把「造成伤害 + 给自己上 Buff」的技能整个判成 `self`。真纪的 EX 曾经 744% 砸自己脸上。
  `resolveTarget()` 里的 `hasDamage` 就是拦这个的，全 272 人里有 14 个技能踩这条。
- **倍率低得离谱**。`HitFrames` 比 `Hits` 长的技能是「固定场地」持续伤害（全 272 人里 5 个：
  惠、千世、纱绫×2、切里诺），真正的跳数在 `HitFrames` 里。不摊开的话千世 4 费的 EX
  只有 56%，比她自己的普通技能还弱。
- **多段 `Damage` 效果只取了第一段**。全 272 人里 45 个技能有 2 段以上，但**不能一律摊开**：
  多数第二段是条件加伤（爱丽丝「能量充能时 ×1.5」、睦月「叠满 6 层时追加」）或随机三选一
  （小雪），那些取第一段才对。只有「对 1 名敌方单位…再对以其为中心的范围」这一种措辞
  （`SPLASH_DESC`，7 个）要拆成 `hits`（主目标吃直击＋爆风）+ `splashHits`（扩散只吃爆风）。
  爱露的两个技能都是这种，漏掉后半截她的 EX 从 566% 缩成 274%。
- **描述里的规则没有结构化字段**。跟触发条件一样要用正则从 `Desc` 抠：
  `parseFalloff()` 抓贯穿/弹跳的逐目标衰减（晴奈 EX 每多打 1 人 −10%、最多 −30%，
  全数据 3 个技能有）。看到「衰减」「贯穿」「几率」这类字眼就去核一下有没有落地。
- **一次性的特殊字段**。艾米 EX 的 `ExtraStatSource: "TargetLostHP"` + `ExtraStatRate`
  在全 272 人里**只出现这一次**：每跳 = 治愈力×Scale ＋ 已损生命×3.46%。漏掉后半截
  她的奶量少一半。这类字段不会有第二个用例，但也就没人替你报错。
- **`Hits` 求和 = N×10000 是「N 次独立打击」不是「N 段」**。睦月的 EX 是 3 个圆各炸一次，
  不拆的话会变成 2 个人各吃 1229%（正确是 3 个人各吃 410%）。判据是 `instanceCount()`：
  求和为整数倍**且**描述里有「对 N 个…范围 / 部署 N 个地雷 / 飞射 N 枚」这种**独立爆炸源**
  的措辞。**光看求和不行** —— 日和（泳装）「发射5发子弹…※合计5发子弹的伤害」求和也是
  50000，但明写了 5 发全打第 1 名；伊织「3 发子弹各对其锁定的敌方单位」也是 3 发打同一批人。

`splashHits` 和 `falloff` 都靠「`targets[0]` 是主目标」成立，所以生成器只在
`enemy_adjacent` / `enemy_all` 上写这两个字段——弹射（`enemy_random`）逐段抽目标，
没有「第几个」的概念。

素材下载**只有 chibi 单独 404** 时，是 kivo 与 SchaleDB 的中文译名对不上（爱露 = kivo 的
「陆八魔 阿露」），在 `fetch-art.mjs` 的 `KIVO_ALIAS` 里补一行，用 HEAD 试出正确写法。

## 折算口径（已冻结的决定，改动会影响全体角色）

集中在 `scripts/emit-roster.mjs` 顶部常量：

| 项 | 值 | 说明 |
|---|---|---|
| `LEVEL` | 1 | 直接取 `Stat1`，不插值 |
| `FORCE_STAR` | 3 | 全体统一 3★，消除 1★/2★ 角色的先天劣势 |
| `SKILL_LV` | 0 | 技能 1 级，取 `Scale[0]` / `Cost[0]` |
| `ROUND_SEC` | 5 | **1 轮 = 5 秒**（见下方「时间刻度」）。四人普攻循环实测 4.0~6.6 秒，与之吻合 |
| `AOE_T1/T2` | 126000 / 300000 | AoE 覆盖面积的三分位，决定打 2/3/全体 |
| `USE_GEAR_SKILL` | true | 有爱用品的角色用强化版普通技能（见下方「爱用品」） |

星级倍率用官方表（`TRANS`，顺序是 `[攻击, 体力, 治疗]`），累加到 `stargrade` 档；**防御/命中/闪避/暴击不受星级影响**。等级 1 时 `stat = ceil(Stat1 × 倍率)`，3★ 为攻击 ×1.22 / 体力 ×1.12 / 治疗 ×1.175。这套能精确复现游戏内面板，改之前先确认真要改。

### 爱用品：只吃技能强化，**绝不吃属性加成**

`Skills.GearPublic`（272 人里 66 人有）是爱用品强化后的普通技能，与 `Skills.Public`
同结构，`buildSkill()` 不用改。`pickPublicSkill()` 有就用它，技能名自带 `+` 后缀。

**属性加成（`student.Gear.StatValue`）不能用，这是硬性的量纲问题**：那些是 `_Base` 定值、
按满级面板标定，本项目 `LEVEL = 1` 直接取 `Stat1`。29 件攻击型爱用品相对自身攻击力的
加成中位数，按 Stat1 是 **288%**、按 Stat100 只有 **29%**——野宫 Lv1 攻击 263，
爱用品 +500 就变成 763（×2.9），爱用品比角色本体还大。要用属性加成，得先把 `LEVEL`
提到满级，那是整套口径重做。

技能强化没有这个问题：倍率是 `Scale`（万分比）、Buff 是 `Coefficient`（百分比），
**与等级无关**。36 件带伤害的倍率提升中位只有 ×1.20。

要注意的：

- **覆盖率 24%**，仍然是有的有有的没有。`USE_GEAR_SKILL = false` 可一键退回。
- **`Special` / `Summon` 的强化版退回 `Public`**（妮露、莲华、歌原），别生成半个空技能。
- **两项抵抗要走 buff 层**：星野的急救治疗+ 加暴伤抵抗、绫音的加暴击抵抗，
  而 `critChance` / `critMultOf` 原本直接读 `tmplOf(tgt)`。现在走 `critResOf` /
  `critDmgResOf`，别改回模板常量。
- **暴击伤害系的 `_flat` 单位是万分比**（10000 = 100%），`format.js` 的 `BP_FLAT`
  和 `applyEffects` 的 `bp` 分支负责换算成百分比再显示，直接印 `1579` 玩家读不懂。
- **还有 6 个 Stat 没映射**，都在池外角色身上，加进 IDS 时生成器会打 `未映射` 告警：
  `EnhanceMystic/Explosion/PierceRate_Base`（5 件，属性增伤，引擎没这个维度）、
  `DefensePenetration_Base`（1 件，防御穿透，要改 `defModOf`）。

## 官方战斗公式（`lib/ba/roster.js` 的 CFG + `engine.js`）

取自 SchaleDB 的实现，不是社区博客的转述（博客把命中常数写成 700，实际是 666.67）：

```
命中率   = 2000 ÷ (max(闪避−命中,0) × 3 + 2000)          命中≥闪避必中
暴击率   = 1 − 4000000 ÷ (max(暴击−暴抵,0) × 6000 + 4000000)
防御系数 = 10000000 ÷ (防御 × 6000 + 10000000)            乘算，不是减法
暴伤倍率 = (暴击伤害 − 目标暴伤抵抗) ÷ 10000
伤害下限 = clamp(稳定值 ÷ (稳定值+1000) + 稳定率/10000, 0, 1)
```

默认值：暴击抵抗 100、暴伤抵抗 5000、稳定率 2000、治疗效果 10000。

### 增益 / 减益的叠加：按原作的 `Channel` 分槽

**`Channel` 就是槽位号**，`sameStatusLayer()` 优先按它判。规律在全 272 人里零例外：
一个 Channel 只装一种属性，而且**正负不混**——攻击力增益走 2/102，防御力增益走 3/103，
防御力减益全在 **603**，暴伤抵抗减益全在 623。

- **同槽只留一层，后放的直接覆盖先放的**（不比大小）。
- **不同槽才共存**，共存时逐层乘算（`factorOf` 的 `Π(1+value)`）。
- 没有 `Channel` 的退回「按施加者分层」：白热化的全局减益，以及原数据本来就不带
  Channel 的 `DamageDebuff`（30 个）。

**别改回「按 sourceKey 分层」** —— 那样真纪 −18.4% 和茜 −29% 会叠成 0.579，
而原作里它俩都是 Channel 603，根本不叠。

由此产生一个真实的配队陷阱：**同槽的两个减防角色不该同队**。EX 永远先于普通技能结算，
所以茜的 EX 减 29% 会被真纪的普技减 18% 覆盖掉，真纪反而帮了倒忙。这是槽位制的固有性质。

另外注意 `LEVEL = 1` 下减防几乎没用：防御系数是饱和曲线，星野（全场最高防御 175）
被减 29% 也只多吃 2.5% 伤害。要让减防有意义得先把 `LEVEL` 提到满级。

克制表在 `TYPE_EFFECTIVENESS`（来自 SchaleDB `config.json`），**非对称**：克制 2.0 / 普通 1.0 / 抵抗 0.5，但**振动打特殊是 1.5**、爆发打弹力是 0.5。`affinity()` 对不认识的属性名会抛错，不会静默返回 1。

**分段独立判定**：多段攻击每一段单独 roll 命中和暴击。这不是可选项——合并判定虽然期望相同，但会让白子 10 段 EX 有 14.5% 概率整发落空，且抹掉段数带来的角色区分度。

## 战场分割（原作机制，别按「一条横排」去想）

**1·2 号位是一个战场，3·4 号位是另一个**，两边各打各的。`zoneOf(idx) = idx < 2 ? 0 : 1`。

普攻 / 普通技能的锁定顺序（`laneTarget`）：

1. **嘲讽** —— 最高，直接无视分割
2. **同战场**；本战场敌人全灭了才越界
3. **战场内优先坦克**（`role === "坦克"`），坦克相当于站前一格替队友挡刀
4. 同号位 → |位置差| 最小 → 编号小

**指定的人已经倒下**（前面一个 EX 先手秒了）：当作没指定，走施法者自己的对线。
同战场是**施法者**这边，不是被点名的人那边——茜站 4 号位点白子，白子死了打茜
同战场（3·4）还活着的人；施法者这边也空了，才越界打最近的。

**不指定目标时一律走 `laneTarget`**，EX 也不例外。曾经有个 `pickBestEnemy`
（估算伤害挑最肥的目标）已经删掉了 —— 看着聪明，实际让玩家猜不到刀会落在谁头上。
己方目标走对称的 `allyLaneTarget`：对位（对自己而言就是自己）→ 同战场最近 → 全场最近。

范围技（`expandAdjacent`）**按目标数分两套规则**：

- **2 目标：贪心找邻居，不跨战场。** EX 指哪打哪是玩家花 Cost 换来的选择权，指了 3 位就打 3·4；
  同战场只剩一个人时当场退化成单体，不会跑去另一边凑人数。
- **3 目标及以上：以主目标为中心的固定窗口 `[idx−half, idx+half]`，允许跨战场。**
  越界的那一发就是**浪费掉**——睦月指定 1 号位只炸 {1,2}，指定 2 号位才炸满 {1,2,3}。
  不能贪心地往另一边多抓一个来凑满，那样边缘位就没有代价了，玩家也失去「往中间指」的动机。

3 目标为什么要放开战场分割：**一个战场只有 2 个人**，不跨就永远达不到设计的目标数，
`count: 3` 会变成一个假数字。而固定窗口根本不「凑人数」，跟那条限制的本意（别跑去另一边找victim）
不冲突。目前只有睦月（三连雷）和日富美（EX 的圆）是 3 目标。

**固定窗口分支必须把主目标排在返回数组第一位** —— `splashHits` 和 `falloff` 都靠 `targets[0]` 认主目标。

`enemy_all` 不受任何限制，照样打 4 个。

**范围技的落点里只要站着人偶，整发就被它接走并退化成单体。** 判断在 `resolveTargets` 的
`wall` 分支，覆盖面按各技能自己的规则算，**不是只看「挡的是不是主目标那一路」**：

- **3 目标看中心窗口**：睦月主目标在 2 位时窗口是 {1,2,3}，人偶挡 1 或 3 位（隔一位）照样拦得住
- **2 目标看战场分割**：白子在 1 位时覆盖 {1,2}，只有人偶跟她同战场才拦

人偶不在 `pool.units` 里、扩散也算不出邻居，所以接走之后必然是单体。

### 连发：`enemy_chain`（伊织）

「发射 3 发子弹，每发子弹各对其锁定的敌方单位」—— **每发单独锁目标**，在 `execute` 里
逐发算（跟 `enemy_random` 一样绕开 `resolveTargets` 的一次性选人）。规则一句话：

> 第一发打玩家指定的；之后每一发都**照普攻的规则重选**（人偶 → 坦克 → 对位 → 最近），
> 但**不能和上一发相同**。

`laneTarget(u, foes, exclude, wallZone)` 的后两个参数就是干这个的。

推论（都在 `target-test.mjs` 第 10 组钉死了，敌 1 位放坦克）：

| 局面 | 三发落点 |
|---|---|
| 指定同战场的 1 位 | 1 → 2 → 1 |
| 指定另一战场的 3 位 | 3 → 回本战场对位 1 → 2 |
| 指定输出，同战场有坦克 | 输出 → **坦克** → 输出（换人之后坦克优先重新生效） |
| 本战场只剩 1 位 | 1 → 1 → 1（没人可换就重复） |
| 人偶挡本战场任一路 | 1 → **偶** → 1 |
| 人偶在另一战场，本战场有人 | 1 → 2 → 1（不接） |
| 本战场打空，人偶也在本战场 | 3 → **偶** → **偶** |
| 本战场打空，人偶在另一战场 | 3 → **偶** → 3（先拆墙再打人） |

四条容易写错的：

- **「不能和上次相同」是「有别人才换」不是硬排除** —— 同战场只剩一个就还是打它。
- **排除要发生在坦克筛选之前**。先排除上一发、再在剩下的人里挑坦克，才是「第二优先的普攻选项」；
  顺序反了会让刚打过的坦克继续吃第二发。
- **连发对人偶是按「战场」拦，不是按号位**（`wallZone = true`）。伊织在 1 位、人偶挡 2 位
  照样接得住。**这个放宽只给连发**：普攻和普通技能仍是「扔哪一路挡哪一路」，
  全局放开的话「扔对面 1 号位就只挡 1 号的刀」那条就废了。
- **人偶的让位条件是「刚打过它 且 本战场还有活人」**。本战场空了就一直打它；
  人偶在另一战场时不算「同战场只剩它一个」，所以下一发照常换人。

每发都在**结算之后**重算目标，所以打死人会自动换人（本战场清空就越界）。

## 持续伤害（`unit.dots`，场地 / 灼烧）

两个来源，都折成同一个 `dot` 效果，但**在图上的表达不一样**：

- **`HitFrames` 场地**（5 个：惠、千世、纱绫×2、切里诺）：`Hits` 只写一段，
  **最后一帧就是场地存续时间**（30fps，千世收在 300 帧 = 10 秒 = 2 轮，与描述的「持续10秒」吻合）。
  总伤害摊到存续的每一轮，`zoneDot()` 负责换算。**别摊平成一次性打完** ——
  那是 616% 的瞬间爆发，跟「持续」的语义完全相反。
- **`DamageDebuff`**（全 272 人 33 个）：灼烧/中毒/冰冻/感电。**它不是「造成伤害降低」**，
  33 个无一例外都带 `Icon` 和 `Period`，当成 `dmg_deal` 减益的话方向都是反的。
  这些**全在 `Passive` / `ExtraPassive` 槽**，而生成器**有意不读那两个槽**：
  池内 20 人的被动共 40 个技能、其中 31 个是常驻 Buff，接进来等于把全体面板重算一遍。
  所以灼烧类目前在池里接不到，等被动系统单独排期。

三条性质（`endTurn` 里的 dots 循环）：

- **不发 `action` 事件** → 战场图不画连线。施加者可能已经阵亡，从他身上拉线是错的；
  伤害直接记在承受者头上，靠 `.fxlabel.dot` 的**橙色**和左侧竖条区分来源。
- **不转移目标**：场地在施放瞬间贴到当时站在里面的人身上。其中一个死了，剩下的照跳，
  但不会跑去烧别人 —— 回合制没有「走进场地」这回事。地上的圈（`side.fields`）
  按技能生效范围落下，人死了既不跟着缩，也不挪到旁边的人身上。
- **召唤物也在列**：人偶站在场地里一样挨烧，所以循环要遍历 `[...side.units, ...summonsOf(side)]`，
  且召唤物的字段里**不能漏 `dots: []`**（漏了场地打到人偶时直接崩）。

**状态格只给灼烧类出，场地不出。** 千世的 EX 是固定场地，**不是 debuff**，
给它挂减益图标是错的表达（`statusMarks` 里按 `icon !== "Zone"` 过滤，也不发 `debuff` 事件）。
战场图在生效范围脚边画一个**蓝色立体圈**（透视椭圆，盖住主目标所在战场的那两路），圈里标剩余轮数。浅蓝在战场底上看不清。
灼烧类出火苗图标、蓝底（减益），多来源合成一格标 ×N。

千世的 ExtraPassive 是普攻 10% 上灼烧，那才是真 debuff —— **被动先不上**，
生成器继续不读 `Passive` / `ExtraPassive`。入场加攻那条被动同样先放下。

**普攻也可能是范围的**（`Skills.Normal` 带 `Radius`，全 272 人 11 个，池内只有千世）。
生成器要把 `resolveTarget` 的结果一起写进 `autoAttack`，只取 `hits` 会把圆形普攻当成单体。
圆形普攻**依旧被人偶挡**：覆盖面里站着人偶，整发被接走，跟她的圆形普通技能同一条规则。

## 换弹强化（`unit.charge`，鹤城）

`Special` + `Key: "FormChange"`：EX 之后的**一梭子**普攻倍率提高、打成扇形（多目标）。

- **发数 = `AmmoCount / AmmoCost`**（鹤城 4/2 = 2 发），别写死。
- **倍率与扇形只写在描述里**：`倍率强化至138%` 用正则抠；打几个人取 EX 自己 `Radius` 算出的 `count`。
- **`thenAutoAttack` 照给**：换完弹当场就能开枪，那一发已经是强化过的，由 `autoAttack()`
  从 `u.charge` 扣掉。所以 2 发的落点是「施放回合 1 发 + 下个回合 1 发」，不是推迟到之后两回合。
- **「换弹后失效」的增益没有 Duration 字段**，让它跟强化射击同寿：`turns = shots`。
  进攻类 Buff 施放回合就算第 1 回合，而第 1 发也在施放回合，所以正好对齐、不用 +1。

引擎侧只有 `autoAttack()` 里一个分支：`u.charge.shots > 0` 就按强化参数打并扣一发。
仍然走 `laneTarget` 选主目标 —— 强化的是威力和覆盖面，不是选择权。

## 召唤物（`side.summons`，不是第 5 个队员）

目前只有日富美的佩洛洛人偶。数据在 `scripts/summons.json`（SchaleDB 同源，20 条），
Q 版图在 `resources/ba/summons/40002/chibi.png`。

**关键决定：召唤物不进 `side.units`。** 进去就得改 `zoneOf` / `exLockLenOf` / `settle` /
战场图的 4 格 —— 全是核心假设。放独立数组之后，`aliveOf` / `sideDead` / `settle` /
EX 冷却读的都是 `units`，**一行都不用改**就天然不把它算进去，这正是我们要的。

只接三个点：`laneTarget`（挡刀）、`applyDamage`（能挨打）、`endTurn`（存活轮数）。

规则：

- **扔在哪＝伤害的主目标那一路**，之后只挡那个号位的刀。「扔对面 1 号位就只挡 1 号的刀」，
  所以 `日富美ex打<某人>` 的选择是有战术含义的。
- **入场那一轮的 Provoke 无视一切**，敌方全员被拉过来打它；之后退化成只挡一路。
- 时长按**敌方回合**跳（跟护盾同口径，它挡的是敌人的攻击窗口），30 秒 = 6 轮。
- 重复施放清除先前那个（原作行为，靠 `sourceKey` 认）。
- 玩家能指名打它：`伊织ex打佩洛洛人偶`，`findSummon()` 允许省略后缀写「佩洛洛」。

只放行 **`AttackPower1/100 === 0`** 的召唤物（`buildSummon` 里挡着）。会打人的炮台
（雷ちゃん 那种）需要「召唤物自己的行动位」，那套还没有，放行只会生成一个不会动的空壳。

**Provoke 必须单独分流**：生成器把所有 `CrowdControl` 一律映射成 `cc`，而引擎的 `cc`
分支写的是 `t.stun`。人偶的入场技能就是 `CrowdControl` + `Icon: "Provoke"`，不分流
就变成「全场敌人晕 1 轮」，比嘲讽强得多。

## 控制（`u.stun`，眩晕 / 恐惧共用一套）

回合制没有移动维度，原作里眩晕（不能动）和恐惧（不能攻击但能移动）最后都落到同一件事，
所以合并成 `u.stun`，只用 `u.stunIcon` 区分**叫法**（`CC_TEXT` 查中文名，别再写死「眩晕」）。

被控的那个回合：

- 整回合跳过，普通技能和普攻都不出（③-a 里 `continue` 并记进 `acted`）
- **不能放 EX**（`validateAction` 拦下）
- **已经就绪的普通技能当场被吞**：抬手被打断，照样走 `consumeSkill()` 进冷却。
  冷却型重新压满；**条件型（星野的急救治疗）会消耗一次 `maxUses`** —— 这是被控的真实代价，
  不是 bug，但改平衡时记得它在这儿。

目前池里只有佳代子带控（EX 全体 100%、普技单体 30%），时长都是 1 轮。
她进池之后打满时限的局才从 0 变成个位数 —— 群控会明显拉长战斗。

战场图画在两排中间那条空带上（`.smRow`），列＝挡的号位，`transform:translateY(±64px)`
贴向自己那一边。**不占号位格**，所以 `LANE_X`、EX 卡、4 格布局都没动。两个坑：
`.sm` 必须 `position:relative`（否则绝对定位的 `.fxstack` 会挂到整条带上、数字飘到正中间），
偏移得用 `transform` 不能用 `margin`（margin 会撑高行，`align-items:center` 再一居中就只剩一半）。

**SchaleDB 没有召唤物的美术资源** —— `images/` 下所有路径都返回同一张 1543 字节占位图，
别浪费时间试。kivo 把佩洛洛当角色收录了，走 `fetch-art.mjs` 的 `SUMMON_ART`。

## 白热化 / FEVER TIME（照搬原作，别按「防拖沓」重新发明）

原作 PvP：**一局 4 分钟，剩余不足 1 分钟进入白热化**，时间耗尽则比双方
「当前血量 ÷ 最大血量」定胜负（`settle()` 本来就是这么算的）。

按 1 轮 = 5 秒折算，全部由 `emit-roster.mjs` 顶部的 `BATTLE_SEC` / `FEVER_LEFT_SEC` 推出来：

| CFG | 值 | 来历 |
|---|---|---|
| `FEVER_ROUND` | 36 | (240 − 60) ÷ 5 轮 |
| `MAX_ROUND` | 48 | 240 ÷ 5 轮 |
| `FEVER_COST_MULT` | 2 | 原作**唯一的基础效果**：EX Cost 攒得明显更快 |
| `FEVER_DEBUFF` | 0.5 | 赛季附加规则（S10/S11 都带）：防御 / 闪避 / 受治疗下降。设 0 可关 |

**触发时点是 `state.round` 不是 `state.turnId`**——理由见下方「时间刻度」。

减益是往 `u.buffs` 里推永久层（`turns: 9999`）实现的，不是在伤害公式里加系数：
状态格会自动画出来，玩家看得见发生了什么。受治疗量因此走 `factorOf(tgt, "heal_taken")`。

以当前 20 人池的节奏（中位 8 轮），2000 局里只有十来局摸到白热化 —— 这跟原作一致，
多数 PvP 在白热化前就结束了。它是为长局兜底的，不承担「逼迫结束」的职责。

## 时间刻度：**1 轮 = 5 秒**，别按 turnId 算

原作双方是**同时**打的，蓝回合与红回合是同一段 5 秒的两次呈现——各自跑完一遍
四人普攻循环。所以流逝的秒数 = `state.round × 5`，`turnId` 只是状态的时间戳，
不是秒表。

引擎里所有时长都**只在自己方的回合跳**，一轮正好跳一次，跟上面这把尺子对齐：

| 计时对象 | 跟谁的回合跳 | 位置 |
|---|---|---|
| 普通技能冷却 / 眩晕 / 嘲讽 / 持续治疗 | 自己方 | `endTurn()` 里 `for (const u of side.units)` |
| 进攻类 Buff（`CURRENT_TURN_STATS`） | 施放方 `b.srcSide` | `tickSide` 判定 |
| 其余 Buff / Debuff | 承受者自己方 `u.side` | 同上 |
| 护盾 | **敌方**（挡的是敌人的攻击窗口） | `u.shieldTickSide` |

于是 `secToTurns` / `msToTurns` 的除数就是 `ROUND_SEC`，`turns: 5` = 5 轮 = 25 秒，
玩家看到的「N 回合」= N 个自己的回合 = N 轮。曾经 FEVER 用 `turnId`、时长用己方回合，
两把尺子差了整整 2 倍，改回去等于把这个 bug 装回来。

## 一个回合内的行动顺序：玩家 EX（一次一个）→ 全体普通技能 → 全体普攻

一次只放一个 EX。放完若 `exCastableOf` 还非空，停住等玩家看图再操作，**不切回合、
不跳冷却、不回 Cost**。发「过」或放不出下一发，才跑 ③-a 技能 / ③-b 普攻。

③ 不是按站位 1→4 逐个挑「技能或普攻」。逐个挑的话，真纪的减防放在 4 号位时三个队友
已经打完了，那回合等于白放，**站位就成了隐藏的强度开关**；分段之后减防/增伤一定赶在本方普攻之前。

配套的两点：

- 眩晕在 ③-a 结算并写进 `acted`，被晕的人在 ③-b 也不普攻。
- **减防吃不吃得到看的是「谁先动」而不是「谁挂的」**：茜的 EX 自带 548% 伤害 + −29% 减防，
  `execute()` 是先 `strike` 再 `applyEffects`，所以她自己那一发是原价。这跟原作一致 ——
  SchaleDB 里她的 `Effect[0]` 是 Damage、`Effect[1]` 才是 Buff。

站位仍然决定**打谁**（战场分割 + 对线锁定），只是不再决定增益/减益的覆盖面。

**持续治疗从施放的那个回合就开始跳**，别给它加 `r.st === T` 的跳过守卫。
Buff / 护盾 / 眩晕有这道守卫是对的（它们在对方回合结算，跳过施放回合才不会白扣一格），
但持续治疗永远由己方施加、也永远在己方回合结算，加守卫等于把第一跳推迟整整一轮——
星野的急救治疗是「生命≤30% 触发、每场限 1 次」的救命技能，延后一轮基本等于没放。
去掉守卫后总跳数不变（还是 `turns` 次），只是第一次落在触发的当回合。

**普通技能开局要压满冷却**：`makeUnit()` 里 `skillCd` 起始取 `trigger.turns` 而不是 0。
「每 X 秒」是周期，第一次落在 X 秒而不是开局；起始给 0 会让开局白送一整轮技能，
先手因为先放而多吃 2~3 个百分点的胜率。条件型（`hp_below`）起始仍是 99。
**普攻触发**（`on_auto`，池里泉 / 明里）起始是 0：第一次普攻就能 roll，只有触发成功才进冷却。
这条**不能**进 ③-a 技能阶段，否则泉每 5 回合必放 431%，跟原作「普攻时 20%、冷却 10 秒」完全相反。

**击杀触发**（`on_kill`，池里鹤城 / 莲见）同样不进 ③-a。判定是**自己的伤害把人（含人偶）打到 0**，队友的刀不算。
鹤城冷却 10 秒 = 2 回合，回血 + 攻速（折成增伤）；莲见没有冷却，击杀就换弹并当场补一枪。

由此约 9% 的局全程一个普通技能都没放出来，**这是对的不是 bug**：冷却 5~6 轮 = 25~30 秒，
而中位局只打 7 轮 = 35 秒，原作里 25 秒的技能在这么短的战斗里同样只放得出一发。

这几条压测查不出来（不变量都满足，只是打错人），规则回归在 `scripts/target-test.mjs`：

```bash
node scripts/target-test.mjs
```

### EX 冷却（不是牌库，别再往回改）

四个角色的 EX 随时可选，放完压冷却。**冷却按「本方之后又放了几个 EX」计，不按回合计**，
长度 = `存活人数 − CFG.EX_COOLDOWN_SLACK`（=2）。实现是一个计数器加一个水位线：
`side.exCasts` 累计释放数，`unit.exCastNo` 记下自己是第几个，差值够了就解锁。

两条保命规则，删任何一条都会出现「全队卡冷却、这回合谁都放不出招」：

1. **人少不锁**：长度取 `max(0, n−2)`，剩 2 人时归零，Cost 够就能连放同一人。冷却是唯一的锁，不要再加「本回合已放过」这种第二把锁。
2. **减员刷新**：己方回合开始时若比上回合少人，清空全部冷却。
   `refreshExOnCasualty()` 必须在 `validateAction` 和 `playerTurn` 里**各跑一次**，
   否则校验说不能放、结算却放得出来。

反死锁性质：最多只锁得住最近 n−2 个施放者，所以可放的人永远 ≥ 2。
`stress-test.mjs` 把这条写成了不变量，改冷却公式先看它还过不过。

### 战场图的表达约定

一条信息只占一个视觉通道，别拿两个通道编码同一件事：

| 信息 | 表达 | 不要 |
|---|---|---|
| 伤害量 | 数字本身，**颜色统一** `#C0342C`、字号固定 | 按暴击/克制换色或换字号 |
| 暴击 | 外框炸成爆裂形，**尖刺长度按暴击段 ÷ 命中段缩放**（`burstPolygon(q)`） | 放大数字、加 CRIT 字样；只看 `crit` 布尔值 |
| 克制 | 数字下面的 WEAK（红字）/ RESIST（蓝字）小字 | 换数字颜色 |
| 多段 | 数字下面的短横，亮的是命中段 | 每段各出一个数字 |
| 谁在挨打 | **数字挂在承受方血条正下方**，压住角色是有意的 | 把数字推到空白处避让 |
| 谁打的 | 带箭头的虚线，**外加数字的排列次序＝出手次序** | 只画虚线不画箭头：两端长得一样，看不出方向 |
| 集火 | 排两列，左→右、上→下；奇数时最后一个独占整行居中 | 往下堆成一长条 |
| 护盾 | 真血**上面**单独一条蓝条 `#2A46D2`，按 `shieldMax` 算比例（刚上盾是满格，被啃多少缩多少） | 压在真血里；拿 `maxhp` 当分母；出数字或挂角标 |
| 治疗 | 绿色 `+数值`，落在被治疗者身上 | — |
| Cost 变动 | 不画，只进文字日志 | — |
| EX 不可用 | **两种遮罩分开**：冷却整张压灰盖平；Cost 没攒够用 `conic-gradient` 扇形扫 | 两种共用一种表达；在卡上写「还需 N」 |
| 出手方式 | 三种笔触：普攻细点线 / 普通技能中虚线 / EX 粗实线 | 全用同一种虚线 |
| 血量 | 血条与盾条都切四段（25/50/75 压白线），**填充仍然是连续百分比** | 按段跳的四级台阶 |
| 总血量 | 顶栏两条，百分比压在条内正中（深字 + 白外发光，红蓝底和浅灰空槽上都读得出） | 写在条外面 |
| 增益减益 | 血条上方 22px 小方块，**红底增益 / 蓝底减益 / 黄底 `!` 技能就绪**，攻击力排第一 | 按「红=坏」配色 |
| 图标 | 一律画成 24×24 的 SVG 图形（见 `ICON`），22px 的方块里塞汉字读不出来 | 用「攻」「晕」这种字当图标 |
| 叠层 | 同属性合成一格，右下角标 `×N` | 每层各占一格 |
| 剩 1 回合 | 整格 `opacity:.4` 变浅，提前预告它就要没了 | 到期才消失，不给预告 |
| 场地 | 生效范围脚边的**蓝色立体圈**（透视椭圆，`#2E7FD4`），圈里剩几轮；人死了圈不缩、不换人 | 正圆贴脸上；浅蓝看不清；橙色；按还活着的人缩圈 |
| 召唤物时长 | 血条下面一条**橙色时间条**，按 `turns / turnsMax` 缩短 | 在名字旁边写剩余回合数字 |
| 号位 | **不显示**。同队禁止重名，指令写 `ex 星野` | 把数字挂回血条旁边或 EX 卡上 |

顶栏只有一行：红方总血条 VS 蓝方总血条，昵称写在条下面。底部只有 EX 卡和 Cost 条。
中间不放轮数、行动方、阵营摘要、补牌顺序这些——都删过一轮了，别再加回去。

**角色对外完全不带序号**：配队和出招都写名字，`findUnit()` 不认编号。
靠的是 `parseDraft` 禁止同队重名（名字唯一 ⇒ 足以定位）。
`engine.js` 的 `resolveCasts()` 把名字换算成内部号位，号位只活在引擎里。
要是哪天放开了重名，序号就得连着指令一起加回来。

## 指令层

所有指令 `#` 可加可不加。出招格式：

```
星野ex              目标走技能默认规则
星野ex打白子         打敌方的白子
星野ex给芹香         给己方的芹香（治疗/护盾/增益）
过                  结束本回合的 EX，结算技能和普攻
```

**中间那个字不是装饰**：双方可以选同一个角色，光凭名字分不出是哪边的，
所以 `打/攻/揍…` 指敌方、`给/帮/治…` 指己方；不写就按技能自己的 `target` 猜边，
猜错了 `resolveCasts()` 会翻到另一边再找一次。

`parseAction` 在**第一段的施放者认不出来时返回 `null`**（而不是报错），让上层放行——
不然群里聊天带个 "ex" 就被当成指令。空格切分用的是「当前段已含 ex 才另起一段」，
所以 `星野ex 打白子` 和 `星野 ex打白子` 都能正确合成一次释放。

一次只放一个 EX。放完若还能再放，停住发图、仍 @ 本人；发「过」或放不出下一发，
才跑普通技能 → 普攻 → 交给对方。提示只要一句「轮到你了，请行动」，Cost / EX / 血量都在图里。

一步固定发三条：**战报转发 → 战场图 → @当前该动手的人**。开局也要 @ 先手。

战报转发的节点由 `mergeTurnLog()` 归并，**一次行动一个节点**（回合头和「过」并进第一个）。
引擎日志是「`[方] 谁干了什么`」加两空格缩进的明细，一行一节点会撑成十几条碎片；
按行动归并后满编约 5 条，正好是玩家读战报的粒度。

图鉴**一律走合并转发**，节点由 `rosterNodes()` 统一产出（按攻击属性一个属性一个节点）。
三个入口共用它：应战时私聊发给双方（`sendRosterToUser`，首节点多一条配队说明）、
私聊发不出去时兜底发群里（`sendRosterByType`）、玩家主动 `档案图鉴`（`guide` 指令）。

**别再退回「一个属性发一条普通消息」**——20 人池要刷三屏，配队时还得往回翻聊天记录。
私聊那条发不出去（没加好友/风控）必须有群里兜底，少了它加不了好友的人整局都开不起来。

`档案图鉴 星野` 点名某人才发角色卡图片，那条不走转发。

图标只表达「是什么」，底色表达「增益还是减益」——两者不重复编码，
所以攻击力增和减共用同一把剑，不做上下翻转。

状态格里目前只有攻击力会出现——技能 1 级时眩晕时长是 0，其余状态也没角色带。
`describeEffect` 对 `inactive` 的效果**直接不输出**，别再写「（技能1级无效）」这种说明。

数字是通过 `fxByUnit()` 按承受方分组、挂进 `unitCell` 的 `.fxstack` 里的，
**不是按坐标绝对定位**——血条位置由 flex 决定，写死坐标迟早对不上。列数由数量决定，
内联下发 `grid-template-columns`。

`BURST` 是长短半径交错的不规则星形（规则星形看着像徽章），序列写死保证每次渲染一致；
它靠一层负 inset 的 `.burst` 背景层撑在文字盒外，所以尖刺再长也不会啃掉数字。

护盾条 6px + 间距 3px + 血条 13px = 22px，正好等于号位徽标的高度，所以有没有盾都不撑高那一行。

## 坑

- **普通技能的触发条件只存在于中文描述文本里**，没有结构化字段。`parseTrigger()` 用正则从 `Desc` 抠「每 X 秒」「生命值不高于 X%」「仅可触发 N 次」。全体 272 人里 78% 是周期触发、31% 带条件、只有 7% 能直接当主动技——加角色时这块最容易出问题，生成后核对一下 `trigger` 字段。
- **技能顶层的 `Duration` 是帧数（30fps）不是毫秒**，那是施放动画时长。要折算的是 `Effect.Duration`（毫秒）。
- **装甲用短名**（轻装/重装/特殊/弹力/复合），要和 `htmlAssets.js` 的 `ARMOR` 键一致。`affinity()` 两种写法都认。
- **生成器是模板字符串套模板字符串**，`emit-roster.mjs` 里要输出到 roster.js 的反引号和 `${}` 必须转义成 `\`` 和 `\${`，否则被外层吃掉。
- **`ATTACK` / `ARMOR` / 攻略页的强调色都是按深色底挑的**，现在四类图全是亮色，凡是当**文字、箭头、细线**用的一律过 `inkOf()` 压暗，否则贯通的 `#F0C547` 在白底几乎隐形。只有**大块填充**（血条、就绪卡的边框）才用原色。
- **HTML 里不要用 emoji**。无头 Chromium 的 emoji 要靠系统字体，Windows 上能出、Linux 服务器没装 Noto Color Emoji 就是豆腐块。护盾一律写「盾」。`format.js` 是纯文本降级、直接发进 QQ，那里的 emoji 没问题。
- **`clip-path` 会把 `box-shadow` 一起裁掉**，平行四边形 EX 卡的描边描不出来。做法是垫一层同形状、大 3px 的 `.frame` 当底板，`.face` 再 inset 进去。想要外发光则用 `filter:drop-shadow()`，它跟随裁剪后的 alpha。
- **亮底上「变淡」等于消失**。EX 卡未就绪时别加白纱提亮（头像本身就浅，在白色 HUD 上直接糊没），要 `grayscale + brightness(.84)` 往下压，再盖一层冷色深纱。
- **阵亡变灰不能套在 `.unit` 上**。数字是 `.unit` 的子元素，`opacity`/`filter` 会一起继承下去，结果「打死这一下」正好最看不清。只作用到 `.hpwrap` / `.art` / `.chips` 三个直接子元素。
- **`.arrows path{fill:none}` 会把箭头一起干掉**。marker 里的箭头也是 `<path>`，而 CSS 声明压过 SVG 的 `fill` 表现属性，结果箭头静默消失。必须写成 `.arrows>path`。marker 按颜色各建一个，别用 `context-stroke`（浏览器支持没保证）。
- **负 inset 的装饰层不占布局**。`.burst` 往外撑 19/22px，但 grid 只按文字盒排版，同一目标连吃几发时相邻爆裂框会咬在一起糊成一片——靠 `.fxlabel.crit` 的 `margin` 手动补回来（纵向 ≥19、横向 ≥22 减去 gap）。
- 战场图不缓存（每回合都变），角色卡和攻略页按 id 缓存 Promise。

## 验证

改 `engine.js` / `roster.js` 之后必跑压测（随机配队跑满整局，逐回合检查 Cost/HP 边界、存活标志一致性、EX 窗口无重复牌且不含阵亡角色，还会故意灌非法目标）：

```bash
node scripts/stress-test.mjs
```

基线（20 人池，2000 局）：**0 错误 · 平均 8.7 轮 · 中位 8 轮 · 先手胜率 ≈50%**。轮数明显变长说明伤害被削弱了，先手胜率偏离 50% 超过 5 个点要查 `SECOND_BONUS`。

**别拿 500 局判断先手胜率**：那个样本量的标准误就有 ±2.2%，看着像偏移的多半是噪声，要看跑 `node scripts/stress-test.mjs 2000`。

脚本的死循环上限 `GUARD_MAX` 从 `CFG.MAX_ROUND` 推导，**别写死数字**——写死过一次，改完 `MAX_ROUND` 后把「打满时限正常结算」的局误报成了「未收敛」。

改 HTML 模板、或改了会进图的文案（CFG、攻略页）之后，四类图**都要**渲染一遍——
容易只测战场图而漏掉角色卡/攻略页/图鉴卡：

```bash
node scripts/render-smoke.mjs
```

约 6 秒跑完，四类各打一行字节数。它在 `finally` 里调 `closeBrowser()`——**别漏**，
浏览器是常驻单例，不关 Chromium 和 node 都不退出。

也**别把它的输出接 `| tail`**：管道要等进程退出才吐字，一旦浏览器没关就看着像卡死。
