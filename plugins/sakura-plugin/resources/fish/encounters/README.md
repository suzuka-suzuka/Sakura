# 钓鱼遭遇本地资源

本目录由离线脚本生成 5 张关卡 PNG 和 `levels.json`。图片只包含 5×6 地图与 `行动 ≤ N`，到达终点时消耗不超过上限就算成功。鱼在上方，收鱼点与玩家岸边在下方。所有图片为程序渲染，不调用 AI 绘图或外部服务。

已接入机器人：普通鱼、异色鱼、噩梦与宝藏通过重量判定后、困难度判定前，以默认 10% 概率触发。好运护符与首领不触发，鱼雷事件不触发。遭遇成功后继续原来的困难度判定，最终捕获成功才发奖。

实际进入水路遭遇后，这一竿不再算完美收竿，不叠加完美收竿经验倍率，也不显示完美收竿提示。未遭遇及好运护符的原完美收竿规则照旧；生图或发送故障未实际进入遭遇时保留原判定。

每次触发都调用 `createFishingEncounterImage()`，重新生成地图、枚举路线、独立模拟校验后渲染 PNG。不会抽取本目录的五张示例图片。进程内记录最近 32 个布局用于去重，行动数避免连续重复；不复用图片。

概率由经济配置的 `fishingEncounterChance` 控制，默认 `0.1`；`0` 关闭，`1` 表示符合条件时必触发。`#钓鱼攻略` 的第五张图包含完整玩法。

## 离线生成

在仓库根目录运行：

```powershell
node plugins/sakura-plugin/scripts/generate-fishing-encounters.mjs --seed sakura-fishing-small-20261007 --count 5
```

相同种子可重现相同地图。改种子可重新生成布局和限制；默认会改写本目录现有编号资源。要保留现有资源，可用 `--out` 指定另一输出目录。

```powershell
node plugins/sakura-plugin/scripts/generate-fishing-encounters.mjs --seed 新的一批 --count 5 --out plugins/sakura-plugin/resources/fish/encounters-next
```

可增加 `--preview <PNG绝对路径>` 输出单独的总览图。正式关卡图片不包含总览的编号。

需要本项目已安装的 Puppeteer 和系统 Chrome，以及项目内的中文字体。页面使用内嵌字体与 SVG，禁止外网请求。Chrome 的独立配置存放在仓库 `.cache/fishing-encounters-chrome`。

只验证现有关卡与图片，不启动浏览器：

```powershell
node plugins/sakura-plugin/scripts/generate-fishing-encounters.mjs --verify
```

规则与生成器回归检查，不需要 Redis 或 Chrome：

```powershell
node --test plugins/sakura-plugin/scripts/test-fishing-encounters.mjs
```

## 条件与生成方法

- 使用有种子的随机水路，枚举从鱼位到收鱼点、不重复经过格子的路线，保留 3～4 条完整路线的布局，再放置水草和漂木。
- 删除不能出现在任何完整路线中的死路分支，减少辨图负担。往返和绕圈不计入额外路线。
- 每条路线的行动数为移动次数加 A 使用次数，再加 B 使用次数的两倍。A/B 没有各自的次数配额。
- 至少有一组“短路障碍多、长路障碍少”的路线，且这两条路线至少有 2 个不同格子。
- 行动上限在 9～13 次中选择。每张图有 1～2 条上限内的路线，至少一条低于上限，也至少有一条超限路线。上限内与超限路线至少有 2 个不同格子。
- 所有可成功路线移动 6～9 格，经过 2～3 个水草或漂木。无解、单通道、所有路线都能成功、搜索超出预算的候选都不会保存。
- 按水路连接去重，左右镜像、仅修改障碍或仅修改限制都视为相同布局。
- 1～5 张的小批次行动上限各不相同；更大批次和运行时逐场生成避免连续重复行动上限。
- 每张图有唯一上方鱼位和唯一下方收鱼点；当前随机生成器输出 5 列 6 行。
- 数据使用 `#` 岸壁、`.` 水路、`S` 鱼位、`G` 收鱼点、`A` 水草、`B` 漂木。清单版本为 4，限制结构为 `limits: { actions: N }`，字段表示上限，不保存答案。旧版关卡清单需要重新生成。

`analyzeEncounterChoices()` 统计不重复经过格子的完整路线，返回每条路线的行动数、上限内/低于上限/等于上限/超限的数量与成本取舍。它有搜索预算；超出预算时生成器拒绝候选，不能把不完整枚举当成完整验证。

`solveEncounter()` 返回全部不超过行动上限的路线，搜索超出预算时抛出错误。判题会独立模拟玩家的整条路线，接受任意满足条件的路径，不和唯一答案字符串比较。剩余行动不必用完，也不要求选择全图最省的路线。

## 钓鱼攻略的玩法文案

出现遭遇后，将鱼从上方沿水路牵引到下方收鱼点，一条消息提交整套操作。每个方向移动一格，不能斜走或进入岸壁，也不能重复经过任何格子，包括起点。

方向可以写中文，也可以写字母：左 `z`、右 `y`、上 `s`、下 `x`。所有字母不区分大小写，可以和中文混写。A、B 也不区分大小写。

只匹配整条由 `上下左右zysxab` 组成的消息，忽略首尾空白，不从说明文字里提取操作串。串中不能夹杂空格、标点或其他字符。不符合字符范围的消息不计作答，不会重置倒计时；符合字符范围但动作语法错误的消息，例如 `abx`，会进入判题并消耗机会。

进入水草须使用 `A＋方向`，进入漂木须使用 `B＋方向`。例如 `az` 表示向左进入水草，`Bx` 表示向下进入漂木。动作只作用于紧接的这一步；普通水路只写方向，不能使用多余 A/B 凑数。

每个方向消耗 1 次行动，A 消耗 1 次，B 消耗 2 次。普通水路一格消耗 1 次，进入水草一格消耗 2 次，进入漂木一格消耗 3 次。B 仍只输入一个字母。起点不计行动，进入收鱼点的移动计 1 次行动。A/B 没有单独配额；总行动数不超过图片下方的上限就成功，少用几次也可以。到达收鱼点后不能还有操作。

例如 `xAxyBx` 分为 `x / Ax / y / Bx`，移动 4 格，使用 A/B 各一次，总计 7 次行动；地形逐步匹配、到达终点且本局上限为 7 或更大时，就能成功。

只允许提交一次答案，首次纯操作串的动作语法或路线错误也会消耗这次机会。聊天、空消息或混入其他字符的消息会忽略。图片发送成功后开始计时；30 秒内成功倍率为 2，30 秒后线性递减，45 秒成功为 1.5，接近 60 秒时趋近 1。60 秒整及之后视为失败，鱼逃走。噩梦和宝藏只增加经验；普通鱼和异色鱼增加金币与经验，奖励四舍五入。噩梦效果、宝箱数量、熟练度、图鉴记录保持原规则。

倍率公式：`t ≤ 30秒时为2；30秒 < t < 60秒时为 2 - (t - 30) / 30`。采用首次答案到达时间，后续强拉或溜鱼的时间不影响已获得的倍率。答错和超时只按一次钓鱼失败结算，不额外扣鱼饵与体力，先前装备损伤保留。生图或发图故障跳过遭遇并继续困难度判定，按原奖励结算。没有 AI 协助拦截。

## 本地判题

把测试者的首次答案与实际耗时填入命令，不需要启动机器人：

```powershell
node plugins/sakura-plugin/scripts/generate-fishing-encounters.mjs --check encounter-01 --answer '测试者的操作串' --elapsed 45000
```

`--elapsed` 为从发图成功到收到首次操作的毫秒数；省略时按 0 毫秒校验。输出正确性、失败原因、总行动数、移动次数、A/B 使用次数和奖励倍率。每次命令是独立验证；机器人通过 `createEncounterAttempt()` / `submitEncounterAttempt()` 保存一次提交状态。

真实指令隔离集成测试，不连接数据库或 QQ：

```powershell
node --experimental-vm-modules --test plugins/sakura-plugin/scripts/test-fishing-encounter-integration.mjs
```
