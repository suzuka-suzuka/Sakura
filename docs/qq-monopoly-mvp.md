# QQ群大富翁 MVP 规则规格

## 1. 产品目标

这个版本服务于 QQ 群内的短局多人游戏，目标是让 2～6 名玩家在 30～45 分钟内完成一局，并且在机器人重启、玩家暂时离线或重复消息的情况下仍能继续。

MVP 的核心体验只有四件事：

- 掷骰并沿环形棋盘移动；
- 购买、升级地产并向其他玩家收取租金；
- 触发机会、税费、补助和看守所事件；
- 通过破产淘汰或达到动态轮次上限后的总资产排名决出胜负。

游戏现金是局内临时数值，不读取、不写入 Sakura 的用户经济账户，也不发放局外奖励。

默认数值以 [`default-24.json`](../plugins/sakura-plugin/resources/monopoly/maps/default-24.json) 为唯一运行时来源；本文中的数值表用于解释规则。

## 2. 默认参数

| 项目 | 默认值 |
| --- | ---: |
| 玩家人数 | 2～6 人 |
| 棋盘格数 | 24 格环形棋盘 |
| 骰子 | 1 枚六面骰 |
| 初始现金 | 8,000 |
| 经过或落在起点奖励 | 1,000 |
| 目标总行动数 | 72 |
| 最大轮次上限 | 24 |
| 地产最高等级 | 3 级 |
| 完整持有同色组租金倍率 | 1.25 倍 |
| 强制变卖回收率 | 70% |
| 等待掷骰 | 60 秒 |
| 等待购买或升级 | 30 秒 |
| 连续未掷骰淘汰阈值 | 3 次 |
| 看守所停留 | 跳过 1 个自己的玩家回合 |
| 未开始房间有效期 | 10 分钟 |

“玩家回合”指一名玩家从等待掷骰到完成结算的一次行动；“轮次”指所有仍在场玩家各完成一个玩家回合。有人在轮次中破产时，不再等待其后续行动。

开局时按玩家数确定本局轮次上限：

```text
本局轮次上限 = min(24, ceil(72 / 开局人数))
```

对应 2～6 人的上限分别为 24、24、18、15、12 轮，让不同人数的总行动量保持在约 48～72 次。

默认数值把玩法定位为“短局资产竞速”：多数对局应在轮次上限结算，破产用于处理高等级租金和现金管理失败，不追求让每局都提前淘汰多人。这样可以减少玩家过早变成旁观者；实际破产率和平均局长要在群测后再从地图 JSON 调整。

## 3. 群命令

所有会改变状态的命令都必须带 `#`，不监听裸数字或裸“是/否”，避免干扰正常群聊。

| 命令 | 使用者 | 作用 |
| --- | --- | --- |
| `#创建大富翁` | 群成员 | 创建本群房间并成为房主 |
| `#加入大富翁` | 群成员 | 加入等待中的房间 |
| `#退出大富翁` | 已加入玩家 | 仅可在开局前退出 |
| `#开始大富翁` | 房主、群管理员、白名单用户 | 人数达到 2 人后开始 |
| `#掷骰` | 当前玩家 | 掷骰并移动 |
| `#购买` | 当前玩家 | 购买刚刚到达的无主地产 |
| `#升级` | 当前玩家 | 升级刚刚到达的自有地产 |
| `#放弃` | 当前玩家 | 放弃当前购买或升级机会 |
| `#大富翁状态` | 群成员 | 查看棋盘、当前玩家和简要资产 |
| `#大富翁规则` | 群成员 | 查看命令和核心规则摘要 |
| `#认输` | 在场玩家 | 退出本局并清算资产 |
| `#结束大富翁` | 房主、群管理员、白名单用户 | 强制结束本群游戏 |

同一个机器人账号下，每个群最多存在一局大富翁；同一个仍在场的玩家同时只能参加一局大富翁。玩家认输或破产后会释放参赛索引，可以加入其他群的新局。

## 4. 生命周期与状态机

```text
LOBBY
  └─ 开始游戏 ─> AWAITING_ROLL
                    ├─ 掷骰/自动掷骰 ─> RESOLVING
                    │                    ├─ 无需选择 ─> TURN_END
                    │                    ├─ 无主地产 ─> AWAITING_PURCHASE
                    │                    └─ 自有地产 ─> AWAITING_UPGRADE
                    ├─ 连续第 3 次超时 ─> SURRENDERED
                    └─ 认输 ───────────> SURRENDERED

AWAITING_PURCHASE / AWAITING_UPGRADE
  └─ 确认、放弃或超时 ─> TURN_END

TURN_END
  ├─ 仍满足继续条件 ─> AWAITING_ROLL
  └─ 仅剩一人或达到本局轮次上限 ─> ENDED
```

`RESOLVING` 是系统内部的原子处理状态，不接受玩家命令。一个命令只有在当前状态、当前玩家和当前玩家回合序号都匹配时才能生效。

## 5. 开局规则

1. 房主创建房间后，玩家在 10 分钟内加入。
2. 同一 QQ 号不能重复加入，人数上限为 6。
3. 房主退出时，房主身份按加入顺序移交给下一名玩家。
4. 开始时至少需要 2 名玩家。
5. 系统随机打乱行动顺序，并为玩家分配互不重复的棋子颜色。
6. 所有人从 0 号起点出发，现金均为 8,000，初始没有地产。
7. 开局时洗混机会牌，并把牌序与抽取位置一起存入会话。

## 6. 玩家回合流程

### 6.1 玩家回合开始

机器人发送当前玩家的 QQ 提及、现金、所在格和 60 秒倒计时。

如果玩家处于看守所：

1. 本次玩家回合直接跳过移动；
2. 看守所剩余停留次数减一；
3. 降为零后立即恢复正常状态；
4. 进入玩家回合结束，不触发所在格事件。

### 6.2 掷骰与移动

当前玩家发送 `#掷骰` 后，由服务端生成 1～6 点：

1. 按棋盘路径前进对应格数；
2. 正常移动每次跨过或落在 0 号起点时获得 1,000；
3. 开局站在起点不获得奖励；
4. 被送往看守所时不获得途中经过起点的奖励；
5. 骰子结果、移动后位置和现金变化必须先持久化，再发送群消息。

MVP 不包含双骰、对子、额外玩家回合或常规反向行走规则。

### 6.3 到达格处理

到达格按以下优先级处理：

1. 执行格子自身效果；
2. 如效果产生移动，按卡牌上的 `resolveDestination` 决定是否继续处理新格；
3. 一次行动最多连续解析 4 个格子，超过时中止连锁并记录错误，防止自定义地图形成死循环；
4. 所有效果结束后进入选择状态或玩家回合结束。

## 7. 格子规则

### 起点 `start`

- 正常经过或落在起点时获得起点奖励；
- 被卡牌直接移动到起点时，是否领取奖励由卡牌配置决定。
- 奖励只由移动模块结算一次，起点格本身不再重复发钱。

### 地产 `property`

- 无主地产：现金足够时进入购买选择；现金不足则直接跳过。
- 自有地产：未满级且现金足够时进入升级选择。
- 他人地产：立即支付租金。
- 已破产玩家不再拥有地产。

### 机会 `chance`

- 从当前机会牌堆顶部抽一张并立即执行；
- 牌堆耗尽后重新洗混；
- 不存在可持有的“保留卡”；
- MVP 只允许配置白名单效果，不执行地图中提供的 JavaScript。

允许的效果类型：

- 增减现金；
- 向前或向后移动；
- 移动到指定格；
- 送往看守所；
- 向每名其他玩家支付或收取固定金额。

### 税费 `tax`

- 向银行支付固定金额；
- 现金不足时进入强制变卖与破产流程。

### 补助 `bonus`

- 从银行获得固定金额。

### 看守所 `jail`

- 正常走到这里只是探访，不受处罚。

### 前往看守所 `go_to_jail`

- 立即移动到看守所；
- 不领取途中经过起点的奖励；
- 跳过下一次自己的行动。

### 休息区 `rest`

- 不产生任何经济或移动效果。

## 8. 地产与租金

### 8.1 购买

1. 玩家只能购买本次移动刚刚到达的无主地产。
2. 发送 `#购买` 后一次性支付标价，地产等级为 0。
3. 不保留最低现金，现金等于标价时也允许购买。
4. 发送 `#放弃` 或 30 秒未选择时，地产继续归银行所有。
5. MVP 不进行地产拍卖。

### 8.2 升级

1. 玩家只能升级本次移动刚刚到达的自有地产。
2. 每次到达最多升一级，最高 3 级。
3. 升级不要求集齐同色组。
4. 现金不足、地产满级、发送 `#放弃` 或超时都会直接跳过。

### 8.3 租金

租金取地图中该地产当前等级对应的 `rentByLevel`：

```text
普通租金 = rentByLevel[当前等级]

完整持有同色组时：
实际租金 = floor(普通租金 × 1.25)
```

同色组倍率适用于所有等级，但不重复叠加。地产归银行或所有者已破产时不收租。

## 9. 支付、强制变卖与破产

所有现金始终保持为非负整数。

当玩家需要支付金额 `D` 时：

1. 现金足够则直接支付；
2. 现金不足时，系统自动变卖地产；
3. 单块地产的回收价为：

```text
原始回收价 = (购地价格 + 升级费用 × 当前等级) × 70%
最终回收价 = 向下取整到 100 的倍数
```

4. 按最终回收价从高到低变卖，金额相同按格子编号从小到大；
5. 被变卖地产立即归还银行并降为 0 级；
6. 现金达到应付金额后停止变卖；
7. 变卖全部地产仍无法付清时，支付现有全部现金，未付部分免除，玩家破产；
8. 向其他玩家付款时，对方只收到实际支付金额；向银行付款时直接销毁；
9. 一张牌涉及多名收款人时，按本局行动顺序逐个结算。

破产玩家从后续行动顺序中移除，可以继续查看棋盘和聊天。

玩家发送 `#认输` 时，现金清零，全部地产无偿归还银行，不向其他玩家分配。

## 10. 超时与掉线

### 掷骰超时

- 第 1、2 次连续未在 60 秒内掷骰：系统自动掷骰并正常结算；
- 自动掷骰后如产生购买或升级机会，直接视为放弃，不再追加 30 秒等待；
- 玩家主动发送一次有效的 `#掷骰` 后，连续超时计数清零；
- 第 3 次连续未掷骰：本次玩家回合开始前按认输处理，不再自动掷骰。

### 选择超时

- 购买或升级等待 30 秒；
- 超时等同于 `#放弃`；
- 选择超时不计入连续未掷骰次数。

### 机器人重启

- 每次状态变化后立即保存完整会话；
- 会话至少包含 `sessionId`、`turnSeq`、状态、玩家、资产、牌堆、截止时间和地图版本；
- 重启后根据 `deadlineAt` 恢复或补执行超时；
- 超时任务必须携带 `sessionId + turnSeq + phase`，不匹配的旧任务直接丢弃，不能修改新局。

## 11. 结束与排名

满足任一条件时结束：

- 仅剩一名未破产玩家；
- 本局最后一个限定轮次中，最后一名在场玩家完成行动；
- 管理员强制结束。

只剩一人时，该玩家立即获胜。达到轮次上限时按净资产排名：

```text
净资产 = 现金 + 所有地产当前强制变卖价之和
```

仍在场玩家排在已经破产或认输的玩家之前；退场玩家保留在最终名次中作为对局记录。

净资产相同依次比较：

1. 现金较多者；
2. 地产数量较多者；
3. 仍相同则由服务端为并列玩家自动掷骰，最高者胜出；继续并列就再次掷骰。

强制结束不计算胜者，只展示结束前的资产快照。

## 12. 群消息与棋盘展示

- 掷骰、移动和到达格效果处理后立即发送一张棋盘图；
- 如果随后需要购买或升级，选择完成后再发送一张反映新归属或等级的棋盘图；
- 没有选择的玩家回合发送一张，有购买或升级选择的玩家回合发送两张；
- `#大富翁状态` 可随时主动查看最新棋盘；
- 棋盘显示玩家位置、地产归属、地产等级、当前行动者和轮次；
- 玩家列表只显示现金与地产数量，详细资产按需放在图片边栏；
- 不主动发送无变化的状态提醒；
- 同一玩家回合产生多段效果时合并为一条结算消息。

## 14. MVP 明确不做

- 玩家间交易、赠与、抵押和拍卖；
- 角色技能、道具、NPC、小游戏和股票；
- 双骰、对子、额外玩家回合；
- 自定义脚本或群友上传地图；
- AI 决策和机器人玩家；
- Web 客户端、实时动画和 3D 棋盘；
- 局外金币、经验、排行榜和成就；
- 旁观者代替当前玩家操作。

这些内容只有在基础局时长、破产率和指令体验验证稳定后再扩展。

## 15. MVP 验收条件

- 2～6 人能够从建房完整游玩到结算；
- 24 格地图首尾闭环，所有地产和机会牌引用均通过校验；
- 重复命令、非当前玩家命令和旧超时任务不能造成二次结算；
- 机器人在任一等待状态重启后可以继续；
- 经过起点、卡牌移动和前往看守所不会重复发放起点奖励；
- 支付、变卖、破产后不存在负现金、重复所有权或遗失地产；
- 一局任何时刻每个群只有一个有效会话；
- 掷骰结算后必须发送棋盘；存在购买或升级选择时，选择结算后必须再发送一次；
- 默认配置下，一局能在约 30～45 分钟内结束。
