## 版本变更

| | v2 | v3 | **v4** |
|---|---|---|---|
| Cost 开局 | 3 | 3 | **0（双方对等）** |
| Cost 回复 | 定额 +3 | 定额 +3 | **每存活角色 +0.5**（满编 2/回合，剩 2 人 1/回合） |
| 「过 +1」 | 有 | 有 | **删除**（回复不该取决于玩家做了什么） |
| Cost 上限 | 12 | 12 | **10** |
| EX 费用 | 2~6 | 2~6 | **2~6 + 一个 10 费终极** |
| 暴击/闪避 | 期望槽 | 期望槽 | **真随机**（给落后方留翻盘空间） |
| 对局长度 | ~8 回合 | ~8 回合 | **~11 回合**（HP×1.4） |

### v4 为什么这么改

v3 的 Cost 系统有个说不通的地方：「本回合没放 EX，回合结束 +1」让**回复速率取决于玩家这回合做了什么**，而原作的 Cost 是恒定速率、与操作无关的。把它改名叫"起手开销"也没用，底层还是同一个不对等。

删掉它之后攒 Cost 立刻变成劣势策略（攒 5 只有 0.41 胜率）。但这不是 bug——对局是消耗战，早花的 Cost 先换人头，人头又换来更多输出，收益是复利的。**「过 +1」只是硬塞一笔利息把这个结构性劣势抹平。**去掉之后"过"就该老老实实地是"我没钱"，而不是一个划算的战略选择。原作里也没人主动屯 Cost。

同时 v3 有个方法论错误：**先配平了角色，再改机制。**改完经济之后旧角色表当然崩（极差 0.21），但那是角色过期了，不是机制不行。v4 的顺序是机制先锁死、测准，再照着它重建 16 个角色。

## 1. 一句话说清这个游戏

**双方各自暗中排出 4 人一排，揭晓后轮流行动；你在自己的回合里只做一个决定——这些 Cost 是现在花掉，还是攒着放大招。**

主轴只有一条：

> **普攻和普通技能被"对线"锁死，只有 EX 能自由选目标。**
> 所以 Cost 的本质不是"伤害资源"，而是**打破对线格局的资源**。

配队决定了 4 条线的先天优劣，EX 是战斗中唯一能翻盘的手段。这条主轴把「暗配队」「属性克制」「Cost」串成一个整体。

## 2. 战场与位置

```
        红方  [1] [2] [3] [4]
              ┆   ┆   ┆   ┆      ← 对位连线
        蓝方  [1] [2] [3] [4]
```

- 双方各 4 个位置，编号 1~4，**按配队时提交的顺序**填入。蓝 1 对红 1、蓝 2 对红 2……
- **角色不移动**，倒下的留空位，不补位。
- 自己回合内，己方角色按位置 **1→4** 依次行动。
- **两侧编号同向排列，不要镜像。** 敌方画成 `[4][3][2][1]` 虽然更像"两军对垒"，但对位连线会变成交叉的，「打临近」的相邻关系在视觉上也跟着反过来。战场图渲染同理，红蓝两行都从左到右 1→4。

### 2.1 目标选择规则（写死，玩家要能心算）

**普通攻击 / 普通技能**（对线锁定），按顺序判定：

1. 敌方存在**嘲讽**角色 → 打它（多个时取编号最小的）
2. 否则敌方**同号位**存活 → 打同号位
3. 否则在存活敌人中取 **|位置差| 最小**者；同距离取**编号较小**者
4. 敌方全灭 → 不行动

> 例：蓝 2 的对位红 2 已阵亡，红方剩 1 和 3，距离都是 1 → 打红 1（编号小）。
> 用"编号小优先"而不是"靠中心优先"，是因为前者玩家扫一眼就能算出来。

**EX 技能**：完全不受对线限制，目标由技能定义（指定单体 / 敌方全体 / 对位三格 / 己方全体 / 自身）。这是 EX 存在的意义。

## 3. 属性与克制

| 攻击属性 | 克制（×1.35） | 被抵抗（×0.75） |
|---|---|---|
| 爆发 | 轻装 | 重装 |
| 贯通 | 重装 | 特殊装甲 |
| 神秘 | 特殊装甲 | 轻装 |
| 振动 | 弹力装甲 | 特殊装甲 |

| | 轻装 | 重装 | 特殊装甲 | 弹力装甲 |
|---|---|---|---|---|
| **爆发** | **1.35** | 0.75 | 1.00 | 1.00 |
| **贯通** | 1.00 | **1.35** | 0.75 | 1.00 |
| **神秘** | 0.75 | 1.00 | **1.35** | 1.00 |
| **振动** | 1.00 | 1.00 | 0.75 | **1.35** |

### 3.1 为什么不是原作的 200% / 100% / 50%

| 克制/被克 | 四线全踩克制的胜率 | 猜中对位并最优排布 |
|---|---|---|
| **2.00 / 0.50**（原作） | **86.7%** | 71.6% |
| 1.50 / 0.65 | 85.5% | 72.4% |
| **1.35 / 0.75**（采用） | **74.6%** | **70.3%** |
| 1.25 / 0.82 | 74.3% | 65.0% |

原作是实时战斗，4 条线的克制不同时锁死，可以靠走位和 EX 时机补救。这里是**盲配 + 固定对位**，克制收益会在 4 条线上同时结算、同时放大。直接搬 200%/50% 的结果是：**配队猜对就赢八成，后面十几个回合的 Cost 决策全成走过场。**

### 3.2 防御属性同时是体质模板

| 防御属性 | 生命 | 防御 | 攻击 | 闪避 | 定位 |
|---|---|---|---|---|---|
| 轻装 | ~4300 | ~195 | ~870 | 55~80 | 脆皮高输出 |
| 特殊装甲 | ~4850 | ~250 | ~700 | 40~120 | 均衡 / 功能位 |
| 弹力装甲 | ~5150 | ~285 | ~655 | 45~55 | 半肉持续 |
| 重装 | ~6000 | ~330 | ~675 | 10~15 | 肉盾 |

有效生命（生命 ÷ 防御减伤系数）重装:轻装 ≈ **1.6 : 1**，攻击力轻装:重装 ≈ **1.3 : 1**。

> 这个比例是调出来的。第一版给到有效生命 2.2:1、攻击 1.19:1，结果 4 名重装角色垄断强度榜（重炮 66.2%），4 名轻装全垫底（咒缚 40.3%）。矫枉过正后又反过来。1.6:1 / 1.3:1 是两类角色打平的那个点。

## 4. 角色属性与伤害公式

### 4.1 五个数值（v3 删掉了行动值）

| 属性 | 作用 |
|---|---|
| 生命 | 归零阵亡 |
| 攻击力 | 所有伤害、治疗、护盾的计算基数 |
| 防御力 | 走减伤曲线，不做减法 |
| 暴击率 | 触发暴击，暴击伤害 150% |
| 闪避值 | 走闪避曲线，完全免伤 |

**行动值已删除。** v2 里它只剩"决定先后手"一个作用，而实测自然对局中高行动值队伍胜率 **49.6%**——完全中性，等于一个不影响任何结果的数字。同时"队内出手顺序"也被验证几乎无影响（见 6.3）。一个不产生任何决策的属性，留在图鉴上只是噪音。

### 4.2 伤害公式

```
单次伤害 = 攻击力 × 技能倍率 × 属性系数 × 防御系数
         × 增伤系数 × 易伤系数 × 白热化系数 × 暴击系数 × 浮动
```

| 项 | 公式 |
|---|---|
| 攻击力 | 基础攻击 × (1 + 攻击力增减%) |
| 属性系数 | 1.35 / 1.00 / 0.75 |
| **防御系数** | **400 ÷ (400 + 实际防御力)** |
| 增伤系数 | 1 + 施法方「造成伤害」修正 |
| 易伤系数 | 1 + 目标「受到伤害」修正（下限 0.10） |
| 白热化系数 | 1 + 0.20 × max(0, 当前回合 − 6) |
| 暴击系数 | 暴击时 1.50 + 暴击伤害加成 |
| 浮动 | ±5% |

**防御用除法不用减法**：防御 200 减伤 33%，400 减伤 50%，800 减伤 67%。减法公式会在低倍率技能上同时出现"打不动"和"破防瞬秒"两个断点，除法曲线没有。

### 4.3 为什么技能强度全部写成百分比

技能倍率是**相对施法者攻击力**的百分比：`伤害基数 = 该角色当前攻击力 × 倍率`。治疗、护盾、灼烧也一样，全部挂在攻击力上。理由有三条：

1. **让攻击力增减真的有用。** 烈风的全队增伤、震荡的全体破防、灵护的攻击力 +18%，如果技能写死固定数值，这些 buff 就只对普攻生效，辅助角色立刻废掉。
2. **数值和技能设计解耦。** 配平时我只动攻击力和生命（`autotune.py` 就是这么干的），不用回去重算 16 个技能的伤害数字。改一个角色不会连锁到技能表。
3. **玩家能横向比较。** "300% 的 3 费"和"700% 的 6 费"一眼能比，"打 2100"和"打 6650"要先知道谁的攻击力多少。

代价是战报上的绝对数字会随 buff 浮动，看起来不如固定值稳定——但这正是我们想要的，buff 生效时数字跳起来才有反馈。

### 4.4 闪避与暴击 —— 真随机

```
闪避率 = min(35%, 闪避值 ÷ (闪避值 + 300))
暴击率 = min(60%, 角色暴击率)
```

**两者都掷骰子。** v3 曾用「期望槽」（概率累加满 100% 必定触发）来压方差，v4 改回真随机，理由是**要给落后方留翻盘的希望**——一场已经打崩的局，如果连运气都不给，输的一方后半程就只是在陪跑。

代价是明码标价的：

| 随机方式 | 配队决定度（1=全靠配队，0=全靠运气） |
|---|---|
| 期望槽 | 0.784 |
| **真随机（v4 采用）** | **0.476** |

**一半胜负交给运气。**配队和 Cost 决策的权重相应减半，这是换取"反击希望"付的价。如果以后要做天梯，建议天梯模式切回期望槽，娱乐局用真随机——引擎里 `RNG_MODE` 一个配置项就能切。

## 5. 三层技能

| 层级 | 触发 | 目标 | 强度 |
|---|---|---|---|
| **普通攻击** | 自己回合自动，无条件 | 对线锁定 | 100% |
| **普通技能** | CD 就绪时**自动替代**当次普攻 | 对线锁定（少数溅射） | 150%~240%，可附带效果 |
| **EX 技能** | 自己回合主动，消耗 Cost | **自由指定** | 2~6 费常规 + 一个 10 费终极 |
| 被动 | 常驻 | — | 只做 3 种 |

普通技能 CD **统一 3 回合**、开局需蓄满，即第 3、6、9 个自己的回合触发。v3 里闪光是唯一的 CD 2，v4 取消了这个特例——独占"最快普技"是个结构性特权，会让它在任何 Cost 紧缩的版本里自动超模。统一 CD 也让玩家不用记 16 个数字，战报上只标一个「⚡3」倒计时。

被动只保留三种：**Cost 引擎**（本人算两个人，即额外 +0.5 Cost/回合）、**顽强**（首次致命保留不死并回 20% 生命，每局一次）、**静态加成**（如暴击伤害 +45%）。

> 被动是复杂度黑洞。每加一个特殊被动，战报就多一行解释。16 人只给 3 个被动是刻意的。

## 6. 回合流程与先后手

### 6.1 单回合流程

一个**大回合**由两个**玩家回合**组成，先手方先打完自己整个回合，再轮到后手方。

```
第 N 回合
├── 先手方回合
│   ① Cost 回复 = 己方存活人数 × 0.5（+被动），上限 10
│   ② 玩家指令：释放任意个 EX（Cost 够即可，同角色 EX 有 1 回合冷却），或「过」
│   ③ 己方 4 名角色按位置 1→4 依次自动行动
│   │      普通技能 CD 就绪 → 放普通技能（替代本次普攻）
│   │      否则             → 普通攻击
│   │      眩晕的角色跳过
│   └── ④ 回合结束：己方角色的持续伤害结算、状态与 CD 倒计时 −1
│           （本回合刚施加的状态不倒计时，见 8.1）
└── 后手方回合（同上）
```

**每个玩家回合只需要一条指令，而且可以在群里公开发。** 后手方看到先手方做了什么再决定，这是后手的天然信息优势。**除了开局配队，全程不需要私聊。**

### 6.2 先后手：为什么不能直接掷硬币

删掉行动值之后，最直觉的做法是随机先后。但先测了一下"先手到底值多少"——不是看平均值，而是**逐对阵**测量：

| 指标 | 结果 |
|---|---|
| 先手方平均胜率（已补偿） | 51.3% |
| **逐对阵摆幅中位数** | **12.5pp** |
| **摆幅超过 20pp 的对阵占比** | **43.2%** |
| 逐对阵摆幅 P90 | 95.8pp |
| 先手更有利的对阵 / 后手更有利 | 38.8% / 29.2% |

**平均是公平的，单局不是。** 在将近一半的对阵里，谁先手值 20 个百分点以上；最极端的一成对阵，先后手直接决定胜负（摆幅 95.8pp ≈ 换一边就换个赢家）。

更麻烦的是这个摆幅**修不掉**。我试了四种补偿方案，平均胜率能拉到 50%，但摆幅几乎不动：

| 方案 | 先手平均胜率 | 摆幅中位 | 摆幅>20pp 占比 |
|---|---|---|---|
| 无补偿 | 73.3% | 55pp | 65.7% |
| 先手首回合不回 Cost | 54.7% | 15pp | 47.1% |
| 先手首回合不行动 | 59.3% | 15pp | 40.0% |
| 后手开局 +3 Cost | 52.8% | 15pp | 46.4% |

摆幅是**结构性**的——它来自阵容交互（谁的爆发能先落地），不来自补偿规则。所以随机先后 = 在 43% 的对局里掷一次值 20pp 的骰子。这跟我们花力气用「期望槽」保住的低方差是矛盾的。

### 6.3 v4 采用：随机先后 + 后手固定补偿 3

> **先手随机决定，后手方开局 Cost +3。**

v4 实测（人头制经济 + 真随机 + 新角色表）：

| 后手补偿 | 先手胜率 |
|---|---|
| 0 点 | 66.4% |
| 1 点 | 61.8% |
| 2 点 | 53.9% |
| **3 点** | **49.0%** |

3 点是唯一落在 50% 附近的整数，换了两代经济这个数都没变过。

**为什么把 v3 的竞价方案降级为可选。** 竞价存在的理由是 6.2 那个"43% 的对阵里先后手值 20pp 以上"的摆幅，而那个数字是在**期望槽**下测的。v4 改真随机之后配队决定度掉到 0.476，单局本来就有一半交给运气，阵容特异的摆幅会被方差淹掉相当一部分——再叠一层竞价，收益变小、规则复杂度却照旧。

如果以后做天梯（那时建议切回期望槽），竞价方案值得重新启用，下面整节原样保留。

<details>
<summary>v3 竞价方案存档（点开）</summary>

> **配队时一并暗投一个 0~5 的数字。投高者先手，并把自己的投额作为额外开局 Cost 补偿给对方。平手则随机。**

先手权的价格曲线（先手方补偿 N 点 Cost 给后手方，v3 经济下测得）：

| N | 先手胜率 | 先手更有利的对阵 | 后手更有利的对阵 |
|---|---|---|---|
| 0 | 72.6% | 76.7% | 2.7% |
| 1 | 67.7% | 67.3% | 10.0% |
| 2 | 60.8% | 56.0% | 17.3% |
| **3** | **50.8%** | **33.3%** | **29.3%** |
| 4 | 44.3% | 19.3% | 44.7% |
| 5 | 38.0% | 14.0% | 56.7% |

竞价校验——让**真正更需要先手的一方**赢下竞价并支付：

| 中标价 | 该方胜率 |
|---|---|
| 出价 2 | 56.1% |
| **出价 3** | **49.0%** |
| 出价 4 | 41.0% |

合理出价区间是 **2~3**，出到 4 以上就是明显亏本，出 0~1 只能捡漏。每一点出价值约 7 个百分点，曲线足够陡，所以竞价是个**有后果的真决策**。

这个机制的好处：

1. **把掷硬币换成定价。** 谁先手不再靠运气，而由双方共同评估决定。
2. **自平衡。** 爆发队愿意付高价抢先手，续航队投 0 让对方去——**谁更需要先手，谁付更多**，这正是先手摆幅大的那 43% 对局需要的解法。
3. **零额外交互。** 出价和配队写在同一条私聊里：`14 5 9 1 / 3`。不多一个回合。
4. **不需要行动值。** 满足"删掉无用属性"的目标。
5. **盲配失手的一方有个小翻盘阀门**——出价是在阵容揭晓前投的，但你至少能根据自己的阵容判断需不需要先手。

> 想更严谨可以用 Vickrey 变体（投高者先手，但按**对方的出价**付款），此时如实出价是占优策略，玩家不用猜对方投多少。代价是规则解释起来绕一层，群游里我倾向首价拍卖，虚张声势本身就是乐趣。

</details>

### 6.4 两种方案共用同一条引擎规则

`SECOND_BONUS` = 后手方获得的开局 Cost。固定补偿模式下写死 3，竞价模式下写入中标价——改一个配置项就能切换，引擎不用动。

**做天梯的话**，建议 BO2 交换先后手，把 6.2 那个结构性摆幅从赛制上抵消掉，比任何补偿规则都干净。

### 6.5 队内出手顺序（一个被验证否定的想法）

我本来想让"位置 1→4 的出手顺序"也成为战术维度，比如把减防角色放前面给队友铺路。实测把带减防 / 挂灼烧 / 增伤的角色放 1 号位 vs 4 号位：

| 队伍 | 放 1 号位 | 放 4 号位 |
|---|---|---|
| 穿甲（普技减防） | 0.400 | 0.406 |
| 虚数（普技挂灼烧） | 0.349 | 0.374 |
| 烈风（全体增伤） | 0.450 | 0.440 |
| 秘仪（治疗） | 0.422 | 0.409 |

差异都在 2.5pp 以内且方向不一致。**原因是严格对线下每个角色打各自的对位，单体减防落在自己那条线上，队友根本吃不到。** 所以位置顺序目前只是个必要的确定性规则，不是深度来源。想让它有深度，得给普通技能加"对敌方全体挂减益"这类共享目标的效果——列在扩展路线第 1 条。

## 7. Cost 系统

| 项 | 值 |
|---|---|
| 开局 Cost | **0**（双方对等；后手方另给 +3 补偿） |
| 每个自己的回合开始回复 | **己方存活人数 × 0.5** |
| 上限 | **10** |
| EX 消耗 | **2 ~ 6**，外加一个 **10 费终极** |
| EX 冷却 | 释放后该角色下 1 个自己的回合不能再放 |

Cost **全队共享**，且**回复速率只取决于场上局势，与你这回合做了什么无关**——这是 v4 的核心原则。满编 4 人回 2/回合，死到剩 2 人就只回 1/回合。

> 小数不落地：回复按 0.5 累加，攒满 1 点才到账。3 人存活时就是"每两回合回 3 点"。

**一局下来每方总共到手约 18.5 点 Cost**（P10 12 / P90 26，平均 11.2 回合）。这个数字是整张费用表的预算天花板。

### 7.1 EX 费用曲线

| Cost | 人数 | 攒几回合 | 目标范围 |
|---|---|---|---|
| 2 | 3 | 1 | 单体 |
| 3 | 4 | 1.5 | 单体强效 / 随机多段 / 自身 |
| 4 | 5 | 2 | 对位三格 / 己方全体 / 敌方全体（弱） |
| 5 | 1 | 2.5 | 己方全体强效 |
| 6 | 2 | 3 | 敌方全体 |
| **10** | **1** | **5** | **敌方全体决胜** |

**费用必须和目标范围挂钩，不能只和倍率挂钩。** 这条是实测逼出来的：给一个 10 费单体技扫倍率，从 900% 加到 3000%，持有方胜率死死卡在 35%——

| 10 费方案 | 持有方胜率 |
|---|---|
| 900% 单体 | 30.3% |
| 1400% 单体 | 34.2% |
| 2000% 单体 | 34.9% |
| 3000% 单体 | **34.8%**（饱和） |
| 450% 全体 | **49.6%**（平衡点） |
| 700% 全体 | 75.0% |

**单体的价值上限是"删掉一个敌人"，超出的伤害全部浪费**，所以倍率再高也换不回攒 5 回合的成本。全体没有这个天花板，伤害摊在 4 个人身上每一点都兑现。

第二条规则：**EX 费用要和角色的生存能力正相关。** 初版把 6 费的「全体破防」装在震荡（轻装，全场最脆）身上，胜率 0.396；倍率从 240% 提到 310% 只换来 0.6pp——瓶颈根本不在输出，它撑不到攒够第二发就死了。改成 4 费、把 6 费位让给全场最肉的灵护（6300/345）之后才正常。

### 7.2 10 费终极技的战略意义

全场只有重炮一个 10 费（敌方全体 620%），而 **Cost 上限正好也是 10**——攒满条就是开大，中途花任何一点钱都会推迟。

它的战略性不在数值大，而在**它是公开的**。按 §10 的设计，Cost 和出招指令全程公开在群里，对手看着你从 6 涨到 8 再到 9，必须决定：是抢在你攒满前爆掉你，还是留着防御 EX 硬接。**攒本身就是一次公开宣战。**

实测重炮胜率 0.490——略低于均值，对一个高方差全押策略来说是合理定位：你赌赢了一发翻盘，赌输了前五个回合等于白打。

### 7.3 「过」不是战略选择，这是对的

删掉 v3 的「过 +1」之后，攒 Cost 全线跌破 50%（攒 5 = 0.41，攒 7 = 0.32）。这**不是需要修的问题**：

对局是消耗战，早花的 Cost 先换人头，人头又减少对方输出，收益是复利的。任何有战损累积的系统里，囤资源都天然被惩罚。v3 的「过 +1」只是硬塞一笔利息把这个结构性劣势抹平，代价是让回复速率取决于玩家行为——不对等，原作也没有。

所以 v4 里「过」老老实实就是"我没钱"或"我在攒终极"。**原作里也没人主动屯 Cost。**

> 模拟器的盲区要说明：`plan_ex` 是按性价比贪心花钱的，它不会为了组合技存钱。真人攒 Cost 的理由是把烈风的全队增伤 +65% 和虚数的 6 费全体引爆塞进同一个回合，这种窗口贪心 AI 打不出来。所以上面那些"攒 Cost 不划算"的数字系统性**低估**了攒的价值。

### 7.4 对局长度与白热化

v4 把生命值整体 ×1.4（`HP_SCALE`），把对局从 ~8 回合拉长到 **~11 回合**。这不是为了拖时间，而是 **10 费终极技需要 5 个回合攒满，8 回合的对局装不下这个策略**。

> **白热化：从第 10 回合起，每过一回合全场受到伤害 +20%（累加），治疗与护盾效果 −25%（累加，下限 15%）。**

起点跟着对局长度从第 7 回合后移到第 10 回合，否则它会把刚拉长的部分又压回去。

### 7.5 胜负判定

1. 一方全灭 → 另一方胜
2. 打满 22 回合 → 比剩余总生命百分比 → 再相同比累计造成伤害 → 再相同判平

实测：平均 **11.2 回合**，中位 11，P10 = 8，P90 = 15，**打满上限 0.0%，平局 0**。
一个大回合两条指令，一局约 **22 次交互、每人 11 次**。比 v3 翻了一倍，这是 10 费终极技的入场费——如果嫌长，把 `HP_SCALE` 调回 1.0 并砍掉 10 费角色即可回到 8 回合。

## 8. 状态效果（只做这 10 种）

| 状态 | 效果 |
|---|---|
| 攻击力 ↑↓ | 百分比修正攻击力 |
| 防御力 ↑↓ | 百分比修正防御力 |
| 造成伤害 ↑ | 该角色打出的伤害乘算提升 |
| 受到伤害 ↑↓ | 该角色承受的伤害乘算修正（下限 10%） |
| 灼烧 | 回合结束按施加者攻击力的百分比掉血，可被引爆 |
| 治疗 | 按施法者攻击力回复生命 |
| 护盾 | 优先吸收伤害的独立血条 |
| 眩晕 | 跳过该角色下一次自动行动（不影响已声明的 EX） |
| 嘲讽 | 强制敌方**普攻/普技**改打自己；不影响敌方 EX 选目标 |
| 反伤 | 承受伤害时按比例反弹给攻击者 |

> 「嘲讽不影响 EX 选目标」是刻意的：EX 若也被嘲讽锁死，就丧失了"打破对线格局"这个唯一定位。

### 8.1 交替回合制下的状态计时（这条踩过坑）

**规则：状态在其所属角色的回合结束时倒计时 −1，但施加它的那个回合不计。**

第一版漏了后半句，结果**潮汐的嘲讽在敌方回合到来之前就过期了**——它在自己回合放嘲讽，回合结束立刻 −1 归零，敌人根本没被嘲讽到。潮汐胜率因此从 47% 崩到 **17.7%**，一个 3 费 EX 完全变成白给。修正后回到 55%。

实现上给每个状态打一个"施加于哪个玩家回合"的戳，结算时跳过本回合刚挂上的。玩家侧的说法是：

> **状态持续 N 回合 = 从施放起，撑过敌方的回合，到你之后第 N 个回合结束为止。**

眩晕、嘲讽、减防、增伤、灼烧、护盾全按这一条走，没有例外。

## 10. QQ 群交互设计

### 10.1 完整流程

```
[群]  A: #档案对战 @B
[群]  bot: A 向 B 发起对战，B 请发送「#应战」（120 秒内）
[群]  B: #应战
[私]  bot →A/B: [角色图鉴] 回复 4 个编号（顺序=1~4号位）
[私]  A: 14 5 9 1                   ← 只有这一步需要私聊
[私]  B: 3 11 7 16
[群]  bot: [战场图] 阵容揭晓！蓝方先手（随机），红方开局 Cost +3

[群]  bot: 【第1回合·蓝方】Cost 2 请出招     ← 开局 0，回合开始回 2
[群]  A: 过                         ← 战斗指令全部群内公开
[群]  bot: [战报图]
[群]  bot: 【第1回合·红方】Cost 5 请出招
[群]  B: 过
[群]  bot: [战报图]
      ...
[群]  bot: 【第3回合·红方】Cost 10 请出招   ← 攒满了，全群都看得见
[群]  B: ex 2
[群]  bot: [战报图] 重炮 決戦炮击！
      ...
[群]  bot: [结算图] 蓝方胜利！共 11 回合
```

**交替回合制的最大体验收益：战斗过程完全不需要私聊。** 轮到谁谁在群里出招，其他人围观。后手方能看到先手方做了什么再决定，这个信息差和"先手要付 Cost"一起构成先后手的平衡。

### 10.2 指令语法（原则：手机单手能打完）

| 指令 | 含义 |
|---|---|
| `#档案对战 @某人` | 发起（不 @ 则挂等待任意人应战） |
| `#应战` | 接受 |
| `14 5 9 1` | **私聊**提交配队（顺序 = 1~4 号位）。也可用角色名 `震荡 穿甲 秘仪 炎火` |
| `过` | 本回合不放 EX（Cost 照常回复，不受影响） |
| `ex 1` | 1 号位放 EX，目标走默认规则 |
| `ex 1>3` | 1 号位 EX 打敌方 3 号位 |
| `ex 1>3 4` | 一次放多个（1 号位打敌 3、4 号位默认目标） |
| `ex 2>友3` | 目标是己方 3 号位（治疗/护盾类） |
| `#认输` / `#战况` / `#图鉴 炎火` | 辅助指令 |

**默认目标规则**（省略 `>目标` 时）：伤害型单体 → 自己的对线目标；治疗型 → 己方生命百分比最低者；全体/自身型 → 无需目标。90% 的回合只要打 `ex 1 4`。

### 10.3 三个必须处理好的细节

**① 配队要走私聊**

这是唯一必须"暗"的环节。注意 Sakura 的 `config.yaml` 里 `blockPrivate: true` 会拦掉私聊，需要为这个插件开白名单，或在 `deal()` 里对处于配队状态的用户放行。

群友嫌私聊麻烦的话，可以提供**群内发送 + 立即撤回**模式（`e.recall()`）作为配置项，但要提醒：撤回有 1~2 秒窗口，手快的截得到。

**② 战报刷屏**

一个玩家回合的文字战报约 6~10 行，一局 22 个玩家回合就是 150~200 行。三个方案按推荐度排序：

1. **Puppeteer 渲染成图片**（推荐）。Sakura 已内置 puppeteer 和 `.puppeteerrc.cjs`，直接复用。一张图放：双方 8 格站位 + 血条 + Cost 球 + buff 图标 + CD + 本回合事件列表。
2. **合并转发**（`e.sendForwardMsg()`），把每回合折叠成一条。
3. 纯文本精简（只报伤害数字，不报公式细节）。

**③ 超时不能靠 setTimeout**

Sakura 是 fork 出来的子进程，崩溃会自动重启，进程内定时器全丢。把截止时间写进 Redis ZSET：

```
ZADD ba:deadlines <unix_ts> <group_id>
```

再用框架的 `Cron("*/15 * * * * *")` 每 15 秒扫一次到期对局。战斗回合超时自动判「过」，配队阶段超时判负或随机配队+出价 0。

### 10.4 Sakura 插件落地骨架

```
plugins/sakura-plugin/
  apps/baBattle.js         # 指令入口（Command 注册）
  lib/ba/
    engine.js              # 战斗内核：纯函数 (state, action) => (state, events)
    roster.js              # 16 角色数值表
    render.js              # Puppeteer 渲染战场图/战报图
    store.js               # Redis 读写 + 分布式锁
    parse.js               # 指令解析
    template/              # HTML 模板
  configSchema.js          # Zod：超时秒数、Cost 参数、竞价开关等
```

| Redis Key | 类型 | 内容 |
|---|---|---|
| `ba:battle:<group_id>` | STRING(JSON) | 完整战斗状态 |
| `ba:battle:<group_id>:lock` | STRING | `SET NX PX 5000` 结算互斥 |

## 13. 后续扩展路线

1. **反滚雪球**（v4 最大的短板）：人头制回复让零封率停在 **28.7%**，三局多就有一局是碾压。目前唯一的对冲工具是 10 费全体决胜——落后方攒满一发能瞬间抹平血线。更彻底的做法是加一个**复活类终极技**（把人头和收入一起拉回来），但引擎现在不支持复活，要新增效果类型。
2. **让位置顺序真正有意义**（见 6.5 的验证）：给部分普通技能加"对敌方全体挂减益"或"给己方全体加增益"的效果，这样把辅助放前排才真能给队友铺路。目前最便宜的深度增量。
3. **第二个 10 费角色**：v4 只做了重炮一个。加第二个时注意 7.1 那两条硬约束——必须是多目标，且必须装在扛得住的身板上。
4. **支援位（+2 人）**：4 主战 + 2 支援。支援不占线、不吃普攻、只能放 EX。最贴近原作、最能扩充配队深度，但会让"打临近"和战场图复杂一档。
5. **禁用（Ban）阶段**：配队前各 Ban 1 人，降低强势角色统治力，并给暗配队加一层公开信息博弈。
6. **地形/场地**：每局随机一张场地，给某个防御属性 +10% 生命或某个攻击属性 +10% 伤害。极低成本增加对局差异。
7. **天梯与赛季**：Redis ZSET 存分。上天梯建议 **`RNG_MODE` 切回期望槽**（配队决定度 0.476 → 0.784）并启用 6.3 的先手竞价，同时 BO2 交换先后手。娱乐局保持真随机。
8. **PVE / BOSS 战**：内核已是纯函数，一侧换成脚本 AI 即可。可做全群协作打 BOSS（每人出 1 角色）。
9. **移动**：等前面都稳了再考虑。加了移动，"对线"这个核心张力就被稀释了，要非常谨慎。
